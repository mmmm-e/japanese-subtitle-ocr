# 검증 범위

이 문서는 공개 합성 샘플과 자동 테스트의 검증 범위를 기록합니다. 개인 영상, 실제 자막 추출 결과 및 개인 환경의 상세 진단 기록은 저장소에 포함하지 않습니다.

## 수행한 검사

- Windows x64 / Rust MSVC에서 `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test --all-targets`, `cargo build --release`를 실행했습니다.
- Rust 테스트 27개: IPC 5개, 기본 파이프라인 5개, 재생 4개, 연속 중복 통합 9개, 좌우 영역·ASS 4개.
- Mock OCR 통합 검증: 실제 FFmpeg 프레임 추출, FFprobe 메타데이터, PTS 샘플링, 한글·일본어·공백 경로, ROI 크롭, 캐시 재사용, 취소, 자막 시각과 저장·재로딩.
- 좌우 Mock 검증: 두 영역의 시작·끝 독립 계산, 같은 문구의 좌우 분리, 한 모델 재사용, 진행률, 취소 및 한 ASS 저장. 6개 ROI 입력을 고유 이미지 3회 인식으로 처리하고 같은 설정 재실행은 OCR 캐시를 재사용했습니다.
- ASS: 겹치는 시간, 센티초 반올림, 개행·서식 문자 처리, 좌우 스타일. FFmpeg/libass 실제 렌더링의 좌우 픽셀을 검사했습니다.
- 연속 중복 통합: 한 글자 흔들림 A-B-A, 대체문자 후보, 실제 글자 이미지 변화, 짧은 문구, 빈 시간, 모델·영역 분리, 이미지 누락, 사용자 수정 보호, 원문 후보 보존 및 직접 선택 병합.
- 재생: 초기 일시정지, 재개, 앞뒤 탐색, 오래된 프레임 배제, 영상 끝, 디코더 오류. 합성 오디오 출력 콜백도 검증했습니다. 사람의 청취로 동기화를 판단한 시험은 아닙니다.

## 실제 모델 실행

NVIDIA RTX 3060 Ti 8GB에서 실제 CUDA 모델 장치를 확인했습니다. 검증 조합은 PyTorch 2.11.0+cu128, Python 3.12, Paddle용 Transformers 5.23.0, CPT용 Transformers 4.51.3입니다.

- Manga OCR CPT: 합성 문장 `今日は楽しかった！`를 CUDA로 인식하고 SRT 저장. CPU를 명시한 별도 실행에서도 장치를 CPU로 올바르게 보고했습니다. CUDA가 없는 별도 PC의 fallback 실행은 검증하지 않았습니다.
- PaddleOCR-VL 1.6: `cargo run --example dual_smoke`로 1920×1080 / 2초 합성 영상의 양쪽 문장을 한 상주 워커에서 인식. 실제 장치 `cuda:0`, 양쪽 모두 `今日は楽しかった！`, 각 구간 0.00~2.00초. 두 행을 유지해 하나의 ASS 및 JSON으로 저장했습니다.
- GUI 자체 framebuffer로 두 영역, 선택 영역 표시, 좌우 자막 오버레이, 결과 표 및 ASS 선택을 확인했습니다. [작업 화면](dual-regions-preview.png), [ASS 실제 합성](dual-ass-preview.png).

합성 한 문장의 실행 확인은 일반 영상의 정확도 수치가 아닙니다. 정답 데이터셋의 CER/Exact Match는 측정하지 않았습니다.

## 남은 검증과 제한

- 실제 마우스 입력을 통한 드래그·버튼·파일 대화상자의 전체 자동 검증은 수행하지 않았습니다.
- Paddle VL CPU 실제 추론, 장시간 고부하, GPU 공유·디스크 부족·드라이버 변경의 스트레스 검증은 남아 있습니다.
- 애니메이션·손글씨·컬러 테롭·움직이는 배경의 포괄적 성능 평가는 남아 있습니다.
- OCR 전 근사 pHash/SSIM 생략, 자동 줄 분리, 경계 정밀화, 음성 시간 정렬, 캐시 용량 제한, 설치 프로그램, macOS GPU는 미구현입니다.
- 자동 중복 통합은 보수적이며 이미지·문구 근거가 부족하면 남겨 둡니다. 밝은 글자 중심 마스크는 모든 자막 색상에 일반화한 검출기가 아닙니다.
- ASS는 하단 좌우 배치이며 원본 테롭의 움직임·스타일을 복제하지 않습니다. ASS 가져오기와 영역 좌표 영속 저장은 지원하지 않습니다.
